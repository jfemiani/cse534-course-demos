One tool call is easy. What about three?

The last lesson gave the model one tool and asked one question that needed it. Most real questions are not that clean. Answering "when and where can I meet Professor Femiani in person this week?" needs two separate facts: office hours and a room number. The model has to call one tool, read the result, decide it still needs more, call a second tool, and only then write an answer.

This repeated call-observe-decide cycle has a name in two different communities. OpenAI's documentation calls it the agent loop. The research paper that first described it calls it ReAct, short for Reason and Act (Yao et al., 2022). Both names describe the same thing: the model alternates between deciding what to do and reading what happened, for as many steps as the question needs.

The demo

This demo gives the model two tools, lookup_office_hours and lookup_room_number, and asks the two-part question above. The loop keeps sending results back and asking again until the model stops requesting tools and writes its final answer. Each step prints what the model asked for and what it got back.

You will not usually write this loop by hand

The loop above is written out in full so every step is visible. It trusts the model to stop asking for tools once it has enough information; production code typically adds a maximum step count as a safety net, so a confused model cannot loop forever.

In practice, OpenAI's Responses API runs this same loop internally whenever you use one of its built-in tools: web search, file search, a code interpreter, or a shell. You describe the tools you want available and the API keeps calling them until it has an answer, without you writing the while loop yourself.

When a task needs more than one agent working together, handing work off between them, OpenAI also publishes an Agents SDK for that. It sits on top of the same Responses API and is worth knowing exists if a project grows past a single loop like the one on this page.
