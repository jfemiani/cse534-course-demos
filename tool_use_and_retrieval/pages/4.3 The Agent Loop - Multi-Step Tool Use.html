One tool call is easy. What about three?

The last lesson gave the model one tool and asked one question that needed it. Most real questions are not that clean. Answering "when and where can I meet Professor Femiani in person this week?" needs two separate facts: office hours and a room number. The model has to call one tool, read the result, decide it still needs more, call a second tool, and only then write an answer.

This repeated call-observe-decide cycle has a name in two different communities. OpenAI's documentation calls it the agent loop. The research paper that first described it calls it ReAct, short for Reason and Act (Yao et al., 2022). Both names describe the same thing: the model alternates between deciding what to do and reading what happened, for as many steps as the question needs.

The demo: let the Agents SDK run the loop

This demo gives the model two tools, lookup_office_hours and lookup_room_number, and asks the two-part question above. Each tool is a plain Python function decorated with @function_tool from the OpenAI Agents SDK; handing both tools to an Agent and calling Runner.run_sync(...) runs the entire call-observe-decide cycle in one line. This is the version to default to: for any task past a single tool call, the Agents SDK is doing real work for you, not just saving typing.

# pip install openai-agents

Seeing the mechanism: the loop, hand-rolled

It is worth seeing the loop written out once, so "the Agents SDK runs the loop for you" is not a black box. This variant calls the plain Responses API directly: it checks response.output for a function_call item, runs the matching Python function, sends a function_call_output item back, and repeats until the model stops asking for tools. It trusts the model to stop on its own; production code typically adds a maximum step count as a safety net, so a confused model cannot loop forever.

# pip install openai pydantic

Mixing your own tools with hosted tools

An Agent's tools=[...] list is not limited to functions you wrote. WebSearchTool() wraps one of OpenAI's built-in tools: it is hosted (cloud-run), meaning OpenAI runs the search itself, so no code on your side executes for that call. Handing the SDK a list with both kinds, [lookup_room_number, WebSearchTool()], changes nothing about the loop: Runner.run_sync(...) still calls whichever tool the model asks for, local or hosted, and keeps going until the model has an answer.

This demo asks one question that needs both: a room number from the local tool and a real news story from the hosted one, so the printed output shows a local tool call next to a hosted tool call in the same run.

# pip install openai-agents

Other ways to skip writing the loop

OpenAI's Responses API also runs an equivalent loop internally whenever you use one of its built-in tools, without the Agents SDK at all: you describe the tools you want available and the API keeps calling them until it has an answer. Reach for whichever is the smallest fit for the task: built-in tools directly on the Responses API for a single hosted capability, the Agents SDK once you have your own tools or more than one agent (or want to mix your own tools with hosted ones, as above), and the hand-rolled loop only when you need to see or control the mechanism directly.
