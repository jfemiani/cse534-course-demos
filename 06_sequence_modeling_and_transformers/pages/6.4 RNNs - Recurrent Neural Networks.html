The N-Gram Language Generation lesson's n-gram model looked at a fixed window of the last few characters and predicted the next one. That window size was the model's order, and the Evaluating LLMs lesson showed that even the best order (3, in that lesson's sweep) still hits a hard ceiling: no matter how you tune it, an n-gram model can never use information further back than its window allows. What if, instead of a fixed window, a model kept a single running summary that updated with every word, and could in principle carry information from the very first word to the very last?

That is exactly what a recurrent neural network (RNN) does. This lesson builds one from scratch and immediately puts it under stress: it trains a real English-to-French translation model, then hands it a sentence long enough to reveal a specific, nameable weakness in how that "running summary" works.

A hidden state instead of a fixed window

An RNN reads a sequence one token at a time. At each step it combines the current input with a hidden state (a fixed-size vector that is supposed to summarize everything relevant about the sequence so far) and produces an updated hidden state. The same weights are reused at every single step; there is no separate "step 1 weights" and "step 2 weights." An n-gram model also has a fixed number of parameters, but its window gives it a hard ceiling: it can never use information further back than its order allows, no matter how far the relevant context actually is. An RNN's hidden state has no such hard cutoff; in principle, it can carry information from the very first token to the very last, however far apart they are. In practice that ability degrades the further back the network has to reach, which this lesson is about to demonstrate directly.

A single RNN layer is often stacked into several layers, the same way a deep feedforward network stacks layers of neurons: the hidden state layer 1 produces at a time step becomes the input layer 2 sees at that same time step, and so on upward. Each additional layer gives the network more capacity to combine information at a single time step, on top of whatever it already tracks across time.

This module's demos use a single layer in every lesson, so the only thing changing from lesson to lesson is the cell type (RNN, then LSTM, then Transformer), not the amount of stacking. Stacking additional layers is a separate, standard way to add capacity to any of these architectures.

Before combining two RNNs into a translation model, look at what one RNN can already do on its own by feeding its own output back in as its next input. Starting from a beginning-of-sequence token, the network predicts a word, treats that predicted word as the next input, and repeats, until it predicts an end-of-sequence token. Generating this way, one self-produced token at a time, is called autoregressive generation, and it is exactly how a plain text-generation model works, the n-gram models from the earlier lesson included, just with a learned hidden state standing in for the fixed window.

A translation model needs two RNNs working together, called an encoder-decoder: the encoder reads the entire English sentence and produces one final hidden state (often called the context vector), and the decoder starts from that single vector and generates the French sentence one word at a time, autoregressively, the same way the single RNN above did. Everything the encoder learned about the source sentence has to survive being squeezed into that one fixed-size vector before the decoder ever sees it. Hold onto that detail; it is the whole story of this lesson.

This same recipe generalizes past text-to-text translation. Replace the encoder with a CNN that reduces an image down to a single embedding vector, hand that vector to the same kind of autoregressive RNN decoder used above, and the result is an image-captioning model instead of a translator; the decoder has no way to tell whether the vector it started from came from an English sentence or a photograph.

The code below is available in full on GitHub at 03_rnn_mt.py; we'll walk through the parts that matter.

Here is the encoder in full. It is nothing more than an embedding layer (turning each word into a vector) and PyTorch's built-in nn.RNN. The only output it keeps is the final hidden state, that single context vector.

The decoder is almost identical, except it also has to turn its hidden state back into word predictions at every step (the self.out linear layer). During training it processes the whole true French sentence at once, one position shifted, a trick called teacher forcing: at each position, the decoder is shown the correct previous word, not its own (possibly wrong) guess, so training stays stable even before the model is any good. At translation time there is no correct previous word to show it, so step() feeds the decoder's own last guess back in, one word at a time; always picking the single most likely next word this way is called greedy decoding.

Greedy decoding is only one way to turn that per-step probability distribution over words into an actual sentence, and it is not the only one worth knowing. Instead of always taking the single highest-probability word, you could sample the next word randomly according to its probability—a word the model rates 20% likely gets picked about 20% of the time, so the same input sentence can produce different, still-plausible outputs on different runs. A temperature parameter controls how sharply that sampling favors the top choices, by rescaling the logits before the softmax: prob = softmax(logits / temperature). A low temperature (below 1) divides the logits up, exaggerating the gap between the best word and the rest, so sampling behaves almost like greedy decoding (deterministic, but repetitive); a high temperature (above 1) shrinks that gap, flattening the distribution so lower-probability words get picked more often (varied, but riskier). A third option, beam search, keeps a fixed number of the most promising partial translations in progress at once (the beam width) instead of committing to one word at a time or one sample at a time; at each step it expands every candidate in the beam by one word, then keeps only the beam-width-many highest-scoring continuations, so an early word that looks slightly less likely on its own but leads to a much better full sentence is not thrown away too soon, the way greedy decoding would throw it away. This demo uses greedy decoding throughout because it is the simplest to read directly off of the model's next-word probabilities; sampling and beam search trade some of that simplicity for variety or for a better-considered final sentence.

Training on real, noisy data

This demo trains on a few thousand English-French sentence pairs streamed from Hugging Face's Helsinki-NLP/opus-100 dataset (built once, shared across every lesson in this module, by mt_data.py). This is real subtitle-derived data, not a hand-curated textbook dataset, and a small fraction of pairs are misaligned or literal subtitle artifacts. The encoder and decoder's hidden state is 256-dimensional (128 for the word embeddings that feed into it); a later lesson activity asks you to reason about what happens if that size changes. Because of that noise, this demo does something the Evaluating LLMs lesson already taught you to do: it tracks validation loss every epoch and keeps the checkpoint with the lowest validation loss, instead of just training for a fixed number of epochs and hoping for the best.

The model is evaluated on five sentences held out from training, the same five sentences every lesson in this module uses. Since the model's own greedy guess can be flatly wrong even when the model has learned something real, this demo also reports a reference loss: how surprised the model is by the correct French translation, whether or not its own guess matches. Lower is better, and it stays a fair comparison even when the greedy output is nonsense.

Why longer sentences hurt more

The encoder has to fit everything worth remembering about the source sentence into one fixed-size vector, updated one word at a time. Each update multiplies the running signal by the same weights again, and during training, the gradient that teaches early words how they mattered has to flow backward through every one of those multiplications to reach them. With enough steps, that gradient shrinks toward zero (the vanishing gradient problem), and the network effectively stops learning from words that are far from the end of the sentence. A longer sentence means more steps for that gradient to shrink across, and more competing information trying to fit into the same fixed-size vector. That is the mechanism behind the pattern in Table 1.

Takeaway

A hidden state gives a recurrent model unlimited context length in principle: there is no hard window like an n-gram model's order. But a plain RNN still forgets earlier words as gradients shrink over many steps, and the entire source sentence still has to survive being squeezed into one fixed-size vector.
