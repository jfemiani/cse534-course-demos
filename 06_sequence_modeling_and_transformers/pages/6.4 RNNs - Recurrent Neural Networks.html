The N-Gram Language Generation lesson's n-gram model looked at a fixed window of the last few characters and predicted the next one. That window size was the model's order, and the Evaluating LLMs lesson showed that even the best order (3, in that lesson's sweep) still hits a hard ceiling: no matter how you tune it, an n-gram model can never use information further back than its window allows. What if, instead of a fixed window, a model kept a single running summary that updated with every word, and could in principle carry information from the very first word to the very last?

That is exactly what a recurrent neural network (RNN) does. This lesson builds one from scratch and immediately puts it under stress: it trains a real English-to-French translation model, then hands it a sentence long enough to reveal a specific, nameable weakness in how that "running summary" works.

A hidden state instead of a fixed window

An RNN reads a sequence one token at a time. At each step, it does not simply feed its own previous output back in as its next input. Instead, it maintains a hidden state: a fixed-size vector, updated once per step, meant to carry forward everything the network has learned about the sequence so far. What matters is exactly what that update depends on: the hidden state produced at the current step is computed from the current input together with the hidden state produced at the previous step, not from the network's previous output. The same weights are reused to do this at every step; there is no separate "step 1 weights" and "step 2 weights."

That dependency, the hidden state feeding back in to produce the next hidden state, is a cycle. The figure below draws it exactly that way: one hidden-state node h, with a self-loop running back into itself, marked with a small black square for a one-step time delay, since h has to finish being written before that same value is read back in as input.

Unfolding that cycle across time steps, shown on the right above, makes explicit what the self-loop was actually doing: hidden state h at time t is produced from the input at time t together with the hidden state at time t-1, which was itself produced from the hidden state at time t-2, and so on, all the way back to the very first token. This is message passing forward through time: each step's hidden state is handed forward to become part of the next step's computation, one link in an unbroken chain. It is this chain, not a fixed window, that in principle lets an RNN carry information from the very first token in a sequence to the very last, however far apart they are. An n-gram model's window gives it a hard ceiling instead: it can never use information further back than its order allows, no matter how far the relevant context actually is. In practice, an RNN's ability to reach arbitrarily far back degrades the further back it has to reach, which this lesson is about to demonstrate directly.

One RNN layer, on its own, has to do two jobs with the same small set of weights: decide what from the current input is worth keeping, and decide how to combine that with everything the hidden state already remembers. A single layer's capacity to do that combining is limited, the same way a single layer of a plain feedforward network is limited in how complex a function it can represent. The standard fix, in both cases, is to stack more layers. A deep feedforward network stacks layers of neurons so that layer 2 works on the (already partially processed) output of layer 1, rather than on the raw input, giving the network more chances to combine features into something more useful. An RNN can be stacked the same way: layer 1 produces a hidden state at each time step, and instead of feeding that hidden state only forward in time, to layer 1's own next step, it is also fed upward, as the input layer 2 sees at that same time step. Layer 2 then runs its own recurrence on top of that, with its own separate weights and its own separate hidden state history. Each additional layer gives the network more capacity to combine information within a single time step, on top of whatever it already tracks across time via the recurrence described above.

This module's demos use a single layer in every lesson, so the only thing changing from lesson to lesson is the cell type (RNN, then LSTM, then Transformer), not the amount of stacking. Stacking additional layers is a separate, standard way to add capacity to any of these architectures.

Before combining two RNNs into a translation model, it helps to see what one RNN can already do entirely on its own, with no second network involved. Start the hidden state at zero and feed in a special beginning-of-sequence token. The RNN produces a new hidden state, and from that hidden state, a probability over every word in the vocabulary, the word most likely to come next. Instead of stopping there, take that predicted word and feed it back in as the input for the next step, exactly as if it had been part of the original sequence all along. The network produces another hidden state, another predicted word, and that word becomes the input after it, and so on, until the network predicts a special end-of-sequence token telling it to stop. Generating this way, one self-produced token at a time, each one feeding into the step that produces the next, is called autoregressive generation (“auto-” because it is regressing, predicting, on its own prior outputs, not on some separate signal). It is exactly how a plain text-generation model works, the n-gram models from the earlier lesson included; the only real difference is that a learned hidden state has replaced the n-gram model's fixed window as the thing being conditioned on.

Translation cannot be done by the single autoregressive RNN above, because that RNN only ever conditions each new word on words it has already generated, and at the very first step of translating, nothing French has been generated yet; the entire English sentence still needs to get into the picture somehow, before a single French word is produced. The standard fix is to use two RNNs together, one to read the source sentence and one to generate the translation, called an encoder-decoder. The encoder is an RNN that reads the entire English sentence, one word at a time, updating its hidden state as it goes, exactly like the RNN described earlier in this lesson, except it is never asked to produce any output word along the way. Only its very last hidden state, after the final English word has been read, is kept; that vector is often called the context vector, because it is meant to summarize the full context of the source sentence in one fixed-size package. The decoder is a second RNN, a separate set of weights, that starts from that context vector as its own initial hidden state (instead of the all-zero starting state the standalone RNN above used) and then generates the French sentence autoregressively, one word at a time, exactly the way the single RNN above did. Everything the encoder learned about the source sentence has to survive being squeezed into that one fixed-size vector before the decoder ever sees any of it. Hold onto that detail; it is the whole story of this lesson.

This same recipe generalizes past text-to-text translation. Replace the encoder with a CNN that reduces an image down to a single embedding vector, hand that vector to the same kind of autoregressive RNN decoder used above, and the result is an image-captioning model instead of a translator; the decoder has no way to tell whether the vector it started from came from an English sentence or a photograph.

Here is the encoder in full. It is nothing more than an embedding layer (turning each word into a vector) and PyTorch's built-in nn.RNN. The only output it keeps is the final hidden state, that single context vector.

The decoder is almost identical to the encoder in structure, except it also has to turn its hidden state back into an actual word prediction at every step; that is the job of the self.out linear layer, which maps the hidden state to one score per vocabulary word.

How the decoder gets its input at each step is different during training than during actual translation, and the difference matters. At translation time (in step()), there is no correct next word available to hand the decoder; it can only feed its own last guess back in as the next input, one word at a time, exactly like the standalone autoregressive RNN above. During training, though, the correct French sentence is known in advance, and if the decoder's early, mostly-untrained guesses were fed back into itself the way translation does, one bad early guess would derail every prediction after it, since the model would be training on its own noise instead of on real French. Instead, training uses a trick called teacher forcing: the decoder processes the whole true French sentence at once, one position shifted, and at every position it is shown the correct previous word from the real sentence, not its own guess, regardless of whether that guess would have been right or wrong. This keeps training stable from the very first epoch, even before the model has learned anything useful, because every prediction is always conditioned on a real, correct history rather than on the model's own possibly-broken one.

Because training and translation feed the decoder different things, the true previous word versus the model's own guess, the model has to learn to work well in the condition it will actually face at translation time, using only its own guesses. Always picking the single highest-probability next word this way, one word at a time, is called greedy decoding, and it is what translate() does.

Greedy decoding is only one way to turn that per-step probability distribution over words into an actual sentence, and it is not the way the N-Gram Language Generation lesson's demo generated text. That n-gram model computed a probability for every possible next character, then called rng.choice(chars, p=probs): it sampled the next character randomly according to those probabilities, rather than always taking the single most likely one. A character the model rated 20% likely got picked about 20% of the time, not 100% or 0% of the time the way greedy decoding would treat it.

That choice was not incidental. Had that n-gram demo picked the single most likely next character every time, the way greedy decoding does here, its output would have been far less varied: the same starting text would produce the exact same continuation every single run, and any character that was merely second-most-likely, even by a hair, would never appear at all. Random sampling is what let that demo's generated text vary from run to run and avoid always collapsing onto the single most probable path. The same tradeoff applies here: translate() uses greedy decoding, so it is fully deterministic, always producing the same translation for the same input sentence, and it can never recover from a case where the single best next word, chosen in isolation, leads to a worse full sentence than a slightly-less-likely word would have.

What the n-gram demo's random sampling did not have is any control over how random the sampling should be. That control is a temperature parameter, and it works by rescaling the model's raw scores (its logits) before turning them into probabilities: prob = softmax(logits / temperature). Dividing by a small temperature (below 1) stretches the gaps between logits apart, so after the softmax the best word ends up with nearly all of the probability and sampling starts to behave almost like greedy decoding again: deterministic and safe, but repetitive. Dividing by a large temperature (above 1) does the opposite: it shrinks the gaps between logits, flattening the resulting distribution so that lower-probability words get sampled more often than they otherwise would, more varied output, but at higher risk of picking a word that does not actually fit. Temperature 1 recovers plain sampling exactly as the n-gram demo did it, sampling straight from the model's own probabilities with no rescaling at all.

A third option, beam search, does not sample or commit to one word at a time at all. Instead, it keeps a fixed number of the most promising partial translations in progress simultaneously (the beam width). At each step, every candidate currently in the beam is expanded by one word in every plausible direction, and then only the beam-width-many highest-scoring full continuations, scored by their running total probability, are kept; every other continuation is discarded. The benefit over greedy decoding: an early word that looks slightly less likely on its own, but that leads to a much better full sentence a few words later, is not thrown away immediately just because it was not the single best choice at that one step.

This demo uses greedy decoding throughout, because it is the simplest to read directly off of the model's next-word probabilities without any extra bookkeeping. Sampling and beam search trade away some of that simplicity, for variety in the first case and for a more carefully considered final sentence in the second.

Training on real, noisy data

This demo trains on a few thousand English-French sentence pairs streamed from Hugging Face's Helsinki-NLP/opus-100 dataset (built once, shared across every lesson in this module, by mt_data.py). This is real subtitle-derived data, not a hand-curated textbook dataset, and a small fraction of pairs are misaligned or literal subtitle artifacts. The encoder and decoder's hidden state is 256-dimensional (128 for the word embeddings that feed into it); a later lesson activity asks you to reason about what happens if that size changes. Because of that noise, this demo does something the Evaluating LLMs lesson already taught you to do: it tracks validation loss every epoch and keeps the checkpoint with the lowest validation loss, instead of just training for a fixed number of epochs and hoping for the best.

The model is evaluated on five sentences held out from training, the same five sentences every lesson in this module uses. Since the model's own greedy guess can be flatly wrong even when the model has learned something real, this demo also reports a reference loss: how surprised the model is by the correct French translation, whether or not its own guess matches. Lower is better, and it stays a fair comparison even when the greedy output is nonsense.

Why longer sentences hurt more

The encoder has to fit everything worth remembering about the source sentence into one fixed-size vector, updated one word at a time, using the same recurrence described at the start of this lesson: each new hidden state is computed from the current word and the previous hidden state, through the same weights, every single step. That reuse is exactly what makes training an RNN harder than it looks.

Training works by computing a loss (how wrong the model's predictions were) and then computing the gradient of that loss with respect to every weight, the signal that says how to adjust each weight to do better next time. For an early word's hidden state to get credit, or blame, for a mistake the decoder makes many steps later, that gradient has to flow backward through every hidden-state update in between, from the later step all the way back to the earlier one, since each of those updates is where the earlier word's influence passed through on its way to becoming part of the final hidden state. This backward flow through the unfolded time steps is called backpropagation through time, and it is shown below: the bold red path traces the gradient of a later step's loss backward, one hidden-state update at a time, to reach an earlier hidden state.

That red path is a product, not a sum: the gradient reaching the earliest hidden state is the later step's gradient multiplied by one partial derivative per intervening hidden-state update, one factor for every red arrow in the figure above. The same weights are reused at every step, so those factors tend to be similar in size to one another. If each one is even slightly less than 1, a very common case in practice, multiplying many of them together shrinks the product toward zero, the same way repeatedly multiplying a fraction like 0.9 by itself drives the result toward zero the more times you do it. This is the vanishing gradient problem: past some number of steps, the gradient reaching an early hidden state is so close to zero that the network effectively stops learning anything from that word, regardless of how relevant it actually was to getting the translation right.

A longer sentence directly makes this worse in two separate ways at once: it means more intervening steps for the gradient to shrink across on its way back to an early word, and it means more words' worth of information competing to fit into that same fixed-size context vector to begin with. That combination, vanishing gradients plus a fixed-size bottleneck, is the mechanism behind the pattern already visible in Table 1: the model's reference loss was lowest on the two short, plain sentences and highest on the longest one.

Takeaway

A hidden state gives a recurrent model unlimited context length in principle: there is no hard window like an n-gram model's order. But a plain RNN still forgets earlier words as gradients shrink over many steps, and the entire source sentence still has to survive being squeezed into one fixed-size vector.
