The last lesson's RNN encoder-decoder had one clear weak spot: reference loss climbed as sentences got longer, because the gradient teaching the network about early words has to travel backward through every single time step, and it shrinks a little at each one. By the time it reaches the start of an eight-word sentence, there is barely anything left to learn from. This lesson fixes that with a change so small that it is really just one line of code, and the improvement it produces is real, not just theoretical.

Adding gates: what actually changes

A Long Short-Term Memory network (LSTM) adds a second piece of state alongside the hidden state: a cell state, designed specifically to carry information across many steps with less decay. At every step, three learned gates (vectors of numbers between 0 and 1, one per cell-state dimension) decide what happens to that cell state: the forget gate decides what old information to discard, the input gate decides what new information to add, and the output gate decides what part of the cell state to expose as the hidden state other layers see. None of these gates are hand-designed; the network learns all three from data, the same way it learns everything else.

Redraw that same cell with the long-term path (the cell state) and short-term path (the hidden state) picked out separately, and one detail stands out: the cell state's path along the top has no weight matrix sitting on it, only pointwise multiplication by the forget gate and pointwise addition of new information. Compare that to the plain RNN's hidden state, which gets multiplied by the same weight matrix W at every single step; that repeated multiplication is exactly what drove the vanishing gradient problem last lesson. The cell state's gradient can flow across many steps without shrinking by a fixed factor each time, because nothing on that path is forcing it to. The gates themselves are sigmoids, so in practice they saturate close to 0 or close to 1, but rarely land on either exactly.

Just like a plain RNN, LSTM layers can be stacked: the hidden state (not the cell state) that one layer produces at a time step becomes the input the next layer sees at that same time step, while each layer keeps tracking its own hidden state and cell state across time independently.

This module's demos keep every lesson to a single layer, for the same reason as last lesson: the only thing changing across the RNN, LSTM, and Transformer lessons is the cell type, not the amount of stacking.

The code below is available in full on GitHub at 04_lstm_mt.py. Compare it line-by-line with last lesson's 03_rnn_mt.py: same embedding layer, same training loop, same evaluation sentences. The only change anywhere in the file is nn.RNN becoming nn.LSTM, plus the state now being a (hidden, cell) pair instead of a single hidden vector.

The decoder shows the same one-word diff. Everything about teacher forcing during training and step-by-step greedy decoding at translation time works exactly as it did last lesson; only the state being passed around is now a pair instead of a single vector.

Same data, same sentences, better on every single one

This demo trains on the exact same opus-100 corpus, the exact same training loop with best-validation-loss checkpointing, and is evaluated on the exact same five held-out sentences as last lesson's RNN. That control matters: if the LSTM does better, gating is the only thing that changed to explain it. One real run produced this (full captured output: 04_lstm_mt.output.txt):

Aggregate validation loss tells the same story: 4.683 for the RNN versus 4.287 for the LSTM, the lowest of either model's 25 training epochs. The greedy translations are still rough at this data scale (“je sais mon père.” is not a correct translation of “I know my job.”), but the model is no longer collapsing to the same generic phrase for every input the way the RNN did, and the reference-loss gap says the underlying probabilities really did improve, not just the surface-level guess.

Notice something else: the LSTM's own greedy guesses are consistently more varied across the five sentences (“c'est ça, ça.”, “c'est le matin.”, “je vais allumer le feu pour nous.”) where the RNN produced almost the same three or four words regardless of input. That variety is itself evidence the LSTM is conditioning more on the actual source sentence, rather than falling back to whatever French phrase was most common in training.

What gating did and did not fix

The gates give the network an explicit, learned mechanism to protect important information across many steps instead of letting it decay by default; that is why the long sentence improved the most in relative terms. But look again at Table 1: the long sentence still has the highest reference loss of the five, for both models. Gating did not remove the fixed-size bottleneck; the decoder still has to start from a single encoder-produced state, no matter how good that state is at retaining information. It just made better use of the same bottleneck. The next lesson removes the bottleneck itself.

Takeaway

Gating is a mechanism, not magic: three learned gates decide what a cell state remembers, forgets, and exposes at each step, and that alone was enough to beat a plain RNN on every held-out sentence with an otherwise identical model, training loop, and dataset. But the encoder-decoder bottleneck (one fixed-size vector standing in for an entire sentence) is still there. For roughly two decades after their introduction in 1997, and especially through the 2010s once GPUs made training them at scale practical, LSTMs (and the closely related GRU) were the default choice for sequence modeling: machine translation, speech recognition, and text generation systems were built on exactly this cell type, gates and all, before the Transformer displaced them starting around 2017. The next lesson asks what happens if a model can look directly at any word of the source sentence instead of relying on a single summary vector at all.
