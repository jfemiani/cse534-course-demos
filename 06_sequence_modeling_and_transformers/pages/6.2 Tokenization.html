Every demo later in this module, the RNN, LSTM, and Transformer lessons, will quietly depend on a shortcut. mt_data.py, the shared data pipeline behind them, builds a closed, word-level vocabulary and falls back to a single <unk> id for any word it has never seen. Its own docstring calls this “a deliberate simplification.” This lesson asks the question that simplification was covering up: what would a tokenizer that never needs <unk> even look like?

The out-of-vocabulary problem

A word-level vocabulary is built once, from whatever training text is available, and frozen. Anything not in that fixed list (a typo, a name, a word coined after the vocabulary was built) gets mapped to the exact same <unk> id as every other unknown word. The model literally cannot tell one unknown word from another.

Byte-pair encoding: building a vocabulary from the bottom up

Production tokenizers take the opposite approach: instead of a fixed list of whole words, byte-pair encoding (BPE) builds a vocabulary of subword pieces, starting from individual characters. The algorithm (Sennrich, Haddow & Birch, 2016, adapting a data-compression technique from Gage, 1994) is a short loop: count how often each adjacent pair of symbols occurs across the training corpus, merge the single most frequent pair into a new symbol, and repeat.

Here it is on a five-word toy corpus (low, lower, lowest, newer, wider), watching the merge table build up one step at a time:

That loop drives the whole algorithm (the full file also has small helper functions for counting pairs and applying a merge, but this is the part making the decisions). After eight merges, the trainer has learned pieces like low and er. Applying those same learned merges to lowering, a word the trainer never saw, still produces a reasonable segmentation. Worst case, an unfamiliar word falls back to one piece per character. There is no such thing as an unrepresentable string anymore, only a longer list of smaller pieces.

Why an LLM struggles to count letters

Module 4.2's function-calling lesson showed a model failing to count the letters in “strawberry.” Tokenization is the actual explanation: a model never sees individual letters, only whatever pieces its tokenizer produced.

tiktoken splits “strawberry” into str, aw, berry: three pieces, none of which is a single letter. Asking the model how many r's are in the word is asking it to count something its own input representation never directly shows it.

Where to get a tokenizer

  • OpenAI models – tiktoken (pip install tiktoken).
  • Open Hugging Face models – transformers.AutoTokenizer.from_pretrained(model_name), or the standalone tokenizers library.
  • Llama- and T5-style models – SentencePiece (Kudo & Richardson, 2018), usually loaded through that same AutoTokenizer.from_pretrained call.

Different model families, different tokenizer libraries, but the same underlying idea: a vocabulary of subword pieces built by merging frequent adjacent symbols, so that no input string is ever truly unrepresentable.
