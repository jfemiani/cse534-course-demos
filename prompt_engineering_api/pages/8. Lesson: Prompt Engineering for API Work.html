A prompt is part of the program

When a Python application calls a language model, the prompt is not casual conversation. It is an input specification. A useful prompt tells the model what task to perform, supplies the information it needs, and describes what a successful result should look like.

Start with four questions:

  • Instruction: What action should the model perform?
  • Context: What facts, audience, constraints, or source material does it need?
  • Examples: Would one or two representative input/output pairs clarify the pattern?
  • Output contract: What form must the result take so a person or program can use it?

More words do not automatically make a better prompt. Add details that remove a real ambiguity, then test whether the change improves the output.

The API request-and-response pattern

An API lets one program request work from another service. An SDK is a Python package that provides convenient functions for making those requests. A client is the object your program uses to communicate with the service.

  1. Your program creates an SDK client. The SDK reads the API key from the OPENAI_API_KEY environment variable.
  2. Your program sends the model name and prompt to the Responses API.
  3. The service performs a billable model operation and returns a response object: a Python object containing the result and related information.
  4. Your program extracts what it needs. The demonstrations introduce plain text first, then conversation state, streamed text, and structured data.

The demonstration code reads the model name from OPENAI_MODEL. This keeps the code independent of one permanently hard-coded model. If the course recommends a different model later, you can change the environment variable without rewriting every file.

Four different application needs

  • One response: Use a simple request when the program needs one complete result.
  • Conversation state: Continue from a prior response when later turns depend on earlier turns.
  • Streaming: Display text as it arrives when responsiveness matters.
  • Structured output: Ask for data that matches a schema when another part of the program must consume it reliably.

These are separate design choices. Streaming does not create memory, and conversation state does not guarantee a machine-readable structure.

Current documentation is part of the work

The OpenAI SDK and recommended models will change. Before accepting AI-generated code, compare it with the current OpenAI API documentation and model catalog. Prefer the current Responses API for these demonstrations.

Each demo page includes a reusable prompt and an example Python file. The prompt tells a coding assistant to consult current documentation. The Python file shows code that was tested when the page was prepared. If code generated later is different, compare both versions with the current official documentation before running the new code.

Before you continue

Before continuing, check that you can explain three ideas in your own words: what an API request does, why the API key stays outside the Python file, and why code that once worked may need revision when an API changes.
