This page creates the lightweight Python environment used for the first course demonstrations. It installs only the packages needed at the start of the course. Retrieval, agent, and local-model packages will be added when you reach those topics.

This setup makes no API calls and does not require a paid API account yet. Later modules will require a modest amount of paid API credit.

1. Install Python and an Editor

  • Install a current supported version of Python 3 from python.org.
  • Install Visual Studio Code or use another Python-capable editor.
  • In VS Code, install the official Python extension. We also recommend installing the official Jupyter extension. Jupyter is not required for this module, but later demonstrations and labs may use .ipynb notebooks; installing it now avoids another setup step later.

2. Create the Requirements File

Create a folder for your CSE 534 work. In that folder, create a plain-text file named requirements-course-start.txt containing exactly:

openai
pydantic
rich

A requirements file records the Python packages needed for a project. Keeping this initial file small makes installation faster and troubleshooting easier.

3. Create and Activate a Virtual Environment

Open a terminal in your CSE 534 project folder. Use one of the following command blocks for your operating system and shell.

Linux or macOS terminal (bash or zsh)

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-course-start.txt

Windows Command Prompt (cmd)

python -m venv .venv
.venv\Scripts\activate.bat
python -m pip install --upgrade pip
python -m pip install -r requirements-course-start.txt

Windows PowerShell

python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-course-start.txt

Your terminal prompt will usually show (.venv) when the environment is active. In VS Code, run Python: Select Interpreter and choose the interpreter inside .venv.

4. Run the Minimal Environment Check

With (.venv) active, type and run both commands:

python -m pip show openai pydantic rich
python -c "import openai, pydantic, rich; print('CSE 534 environment ready')"

The first command displays information about the three installed packages. Using python -m pip ensures that pip belongs to the Python interpreter currently selected in your environment. The second command confirms that Python can import all three packages successfully.

If everything is working, the final line will be:

CSE 534 environment ready

5. Capture Evidence for Lab 1

Choose one of these forms of evidence:

  • Screenshot: capture the terminal showing (.venv), the commands you entered, and the successful output.
  • Canvas Studio recording: make a short recording in which you show the active environment, type or run the two commands, and show the successful output.

Lab 1 explains exactly how to submit your chosen evidence. Do not include an API key, password, token, or other secret in a screenshot or recording.

Troubleshooting

  • python is not recognized: restart the terminal after installing Python, or try py on Windows and python3 on Linux/macOS.
  • PowerShell blocks activation: use the Command Prompt instructions above, or ask your instructor or campus support for the approved PowerShell execution-policy procedure.
  • A package is missing: confirm that (.venv) appears in the terminal, then run the requirements installation command again.
  • VS Code uses the wrong Python: run Python: Select Interpreter and choose the interpreter inside .venv.

API Key Safety for Later Modules

You do not need to create or store an API key for this module. When later modules require one, provide it to Python through an environment variable named OPENAI_API_KEY. A later setup page will show the exact commands and may use a local .env file to load that variable.

If a project uses a .env file, keep that file only on your computer and add .env to .gitignore before using version control. Never place an API key directly in Python code or a notebook, and never expose it in a screenshot, recording, submitted file, chat message, or version-control repository.

In short: an API key belongs in a local environment variable (or a local, ignored .env file that supplies that variable). It must never appear in code or anything you share or submit.
