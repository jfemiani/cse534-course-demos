Probability and likelihood answer different questions.

Probability and likelihood answer different questions about the same model. Probability treats the model parameters as known and asks what data we might observe. Likelihood treats the observed data as known and asks which parameter values would make that data most plausible.

For example, suppose we flip a coin where μ is the probability of heads. If μ is fixed at 0.70, a probability calculation asks what fraction of heads we might observe in 100 flips. On the other hand, after we actually observe 70 heads in 100 flips, a likelihood calculation keeps those observations fixed and compares candidate values such as μ = 0.50, 0.60, or 0.70. The candidate that makes the observed data most plausible has the greatest likelihood.

The probability formula and likelihood formula can contain the same factors. What changes is what we hold fixed. Probability treats the model parameter as known and considers possible data. Likelihood treats the observed data as known and compares possible parameter values.

Is likelihood a probability? Some textbooks claim likelihood is not a probability. The likelihood function L(θ; x) is built from probabilities but does not integrate to one over the parameters θ, so it is not a probability distribution over parameters. Notice that the likelihood term in the Bayes formula is a probability over evidence, not parameters. 

Independent observations

Independent observations mean that learning one result does not change the probability assigned to another. That is, p(xi|xj)=p(xi), which simplifies the product rule so that p(xi,xj)=p(xi)p(xj),xi⊥xj. We use the upside-down T shape (⊥) to indicate independence. In machine learning, we like to work on problems where data is i.i.d., that is, that each observation is independent of the others, but that they all share a common distribution with the same parameters. In Equation (3.1), θ stands for any parameter or group of parameters. The uppercase L names the likelihood. The ∏ symbol tells us to multiply the probability of every observed result.

L(θ;x1,…,xn)=∏i=1np(xi|θ)
(3.1)

Products of many probabilities quickly become extremely small, which is awkward for a computer to represent. A logarithm changes multiplication into addition. Equation (3.2) therefore replaces the product in Equation (3.1) with a sum but chooses the same best value of θ. The symbol ℓ is a script lowercase ell and names the log-likelihood. The ∑ symbol means to add the terms.

ℓ(θ)=logL(θ)=∑i=1nlogp(xi|θ)
(3.2)

Maximum likelihood for a Bernoulli variable

For Bernoulli data, maximum likelihood chooses the probability of 1 that matches the observed fraction of 1s. Equation (3.3) uses the same notation as Lesson 1: μ̂ML, read “mu hat sub M L,” is the maximum-likelihood estimate of μ.

μ^ML=1n∑i=1nxi
(3.3)

This is the sample mean because Bernoulli observations are coded as zero and one. Adding the observations counts the 1s, and dividing by n converts that count into the observed fraction of 1s.

Brief derivation: For Bernoulli data, the log-likelihood is

ℓ(μ)=∑in[xilogμ+(1−xi)log(1−μ)]

Taking the derivative with respect to μ:

∂ℓ∂μ=∑in[xiμ−1−xi1−μ]

Set the derivative to zero:

∑in[xiμ−1−xi1−μ]=0

Distribute the sum:

1μ∑inxi−11−μ∑in(1−xi)=0

Note that the sum of (1 − xi) equals n − Σxi:

1μ∑inxi=11−μ(n−∑inxi)

Cross-multiply:

(1−μ)∑inxi=μ(n−∑inxi)

Expand and simplify (the μΣxi terms cancel):

∑inxi=μn

Divide both sides by n:

μ^ML=1n∑inxi

Negative log-likelihood as a loss function

Machine learning minimizes the negative log-likelihood (NLL) rather than maximizing likelihood. Since maximizing ℓ(θ) is equivalent to minimizing −ℓ(θ), this is the same optimization problem. The demonstration below shows that gradient descent on raw likelihood fails because the gradients vanish due to numerical underflow, while gradient descent on NLL succeeds.

Neural networks call −ℓ(θ) the loss function and use gradient-based optimizers like Adam or SGD to find parameters that minimize it. For classification tasks, the NLL is called cross-entropy loss. For regression with Gaussian noise assumptions, minimizing NLL is equivalent to minimizing mean squared error. In both cases, we are performing maximum likelihood estimation via gradient descent on the negative log-likelihood.

This connection is fundamental to modern deep learning: training a neural network is maximum likelihood estimation. The billions of parameters in large language models are optimized by minimizing NLL (cross-entropy) over massive text corpora, which is mathematically equivalent to finding the parameters that maximize the likelihood of the observed training data.

Run the demonstrations.

The demonstrations have three parts that illustrate why log-likelihood is essential for modern machine learning.

Part A: Numerical stability. When you multiply thousands of probabilities together (as in Equation 3.1), the product rapidly approaches zero. Python represents these tiny numbers as 10-267 or smaller, eventually reaching exact zero through underflow. The demonstration compares four candidate values of μ and shows that all four likelihoods underflow, making it impossible to determine which is best. In contrast, the log-likelihoods remain computable as ordinary negative numbers like -614 or -693. The key insight: multiplication becomes addition under the logarithm, and addition is numerically stable even when individual terms are extreme.

Part B: Gradient ascent failure. Neural networks do not search over a grid of candidate parameters. Instead, they use gradient descent to iteratively improve parameters. This demonstration shows an attempt to maximize raw likelihood starting from μ = 0.30 (far from the true value of 0.70). When we try to maximize raw likelihood using gradients, the tiny likelihood values cause the gradients to vanish—the parameter stays stuck at 0.30. The gradient computation produces zeros or NaNs, making optimization impossible.

Part C: Direct mu optimization. This demonstration shows gradient ascent on log-likelihood by optimizing μ directly. It succeeds and recovers μ ≈ 0.70, matching the observed fraction. However, this approach requires manual clamping to keep μ ∈ (0,1) at every step—without clamping, the gradient update could push μ outside the valid range.

The demos use PyTorch to show the connection to modern ML training. The same torch.log, gradient computation, and optimizer steps appear in training loops for GPT, BERT, and other neural networks.
