The LSTM fixed part of the RNN's problem: gating let the network protect information across more steps than a plain RNN could. But even with gating, the decoder still starts from exactly one vector, whatever the encoder's last step happened to produce, and that vector still has to stand in for the entire source sentence. What if the decoder did not have to rely on a single summary at all, and could instead look directly at any word of the source sentence, every single time it generates an output word?

That is attention, and it is the core idea behind the Transformer, the architecture behind GPT, ChatGPT, and every other modern large language model. This lesson trains a small Transformer on the exact same task, data, and evaluation sentences as the last two lessons, then looks directly at its attention weights to see what "looking at any word" actually means in practice. The second half of this lesson turns from architecture to training: how does a model like this get turned into an assistant that follows instructions, through reinforcement learning from human feedback (RLHF)?

Attention: a learned, per-step lookup

Recall Module 4's retrieval demos: given a query, you compared it against a set of candidate vectors using a dot-product similarity score, then used those scores to decide which candidates mattered. Attention is that same idea, but learned end-to-end and used inside the network itself, at every decoding step. At each step, the decoder builds a query from what it has generated so far, compares it against a key vector for every position in the source sentence, turns those similarity scores into a set of weights that sum to 1 (a softmax), and uses those weights to combine the corresponding value vectors into a single, freshly-computed summary, one that can be completely different at every decoding step, unlike the encoder-decoder's one fixed vector.

The code below is available in full on GitHub at 03_transformer_mt.py. The encoder here is just PyTorch's built-in nn.TransformerEncoder; nothing hand-rolled. The decoder is built from PyTorch's built-in nn.MultiheadAttention blocks directly, rather than PyTorch's built-in nn.TransformerDecoderLayer, for one specific reason: doing it this way makes the cross-attention weights easy to pull out afterward for the visualization later in this lesson. The attention math itself is entirely PyTorch's; nothing about the computation is hand-rolled.

Notice there is no hidden state being carried from step to step anywhere in that method. Every call recomputes cross-attention fresh, over every encoder output position at once. That is the whole architectural difference from the last two lessons: no recurrence, no fixed-size bottleneck vector, just a learned lookup, recomputed at every step.

Look at the three steps inside that method in order. Self-attention comes first: the decoder attends over its own previous output words, the same query/key/value mechanism described above, but applied to what the decoder has generated so far rather than to the source sentence, so each position can take into account the words that came before it. Cross-attention comes second: this is the step that looks at the source sentence, using the decoder's state as the query and the encoder's output as both keys and values, which is what actually removes the fixed-size bottleneck. A feedforward layer comes last, a plain two-layer neural network (visible as self.ff in the code above) applied independently at every position, giving the model some extra capacity to transform each position's representation after attention has gathered the relevant information.

From next-token predictor to instruction-following assistant: RLHF

Everything trained in this module so far, including the Transformer above, is trained the same way: predict the next token, given the true previous tokens, and be penalized by how surprised you are by the true answer. That objective, run at a vastly larger scale on internet-scale text, is exactly what produces a base model like GPT's pretrained checkpoint. But a model trained only that way will happily continue a prompt in whatever way is most statistically likely, rather than actually trying to help the person asking. Turning a raw next-token predictor into an assistant like ChatGPT that follows instructions and gives helpful, safe answers takes an additional training pipeline built on top of pretraining, commonly called reinforcement learning from human feedback (RLHF).

RLHF is usually described in three stages:

  • Supervised fine-tuning (SFT). Starting from the pretrained base model, continue training (with the same next-token objective as before) on a smaller, curated dataset of high-quality instruction/response pairs written or selected by humans. This alone nudges the model toward an assistant-like response style, but it can only ever imitate the specific examples it was shown.
  • Reward modeling. Humans compare pairs of model responses to the same prompt and say which one they prefer. A separate reward model is trained on those comparisons to predict a scalar score for how good a response is, standing in for human judgment at a scale no human could keep up with directly.
  • Reinforcement learning (commonly PPO). The SFT model is now treated as a policy: it generates a response, the reward model scores it, and an algorithm called Proximal Policy Optimization (PPO) updates the model's weights to make higher-reward responses more likely, while a penalty term keeps the updated model from drifting too far from the original SFT model in any single update, so training stays stable.

Here is the trap built into that pipeline: the reward model is only ever an approximation of what humans actually want, trained on a finite set of comparisons. Optimizing hard against an imperfect proxy for a goal, rather than the goal itself, is exactly Goodhart's Law again, the same failure mode Module 5 named when a metric like cross-entropy stopped tracking writing quality once something started optimizing directly for the number. Here, the "something" is PPO, and the number is the reward model's score. Push too hard against that score and you can get reward hacking: outputs that score well by the reward model's own numbers, often by being longer, more hedged, or superficially more agreeable, without actually being more helpful or correct. The KL penalty against the original SFT model is one guardrail against exactly this failure, but it is a mitigation, not a guarantee; it is the same tension between a measure and the thing the measure is supposed to stand in for that this course keeps returning to. (“KL” here is the same KL divergence from Module 3: a way of measuring how far one probability distribution has drifted from another, now used to keep the model's updated behavior from drifting too far from the SFT model it started from.)

Takeaway

Attention replaces a single fixed-size summary vector with a fresh, learned lookup at every decoding step, computed directly from the source sentence rather than from a bottleneck. On this module's small-scale task, that produced the best aggregate validation loss of the three architectures, while still showing, on one sentence, that a single example can defy the aggregate trend, and that attention alignment at this scale is a real mechanism, not yet a clean picture. RLHF is the separate step that turns a model like this one, once trained far larger on far more data, into an assistant that tries to do what you actually asked, and it carries the same measure-versus-target tension this course has returned to since Module 5.
